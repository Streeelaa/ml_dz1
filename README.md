# Tabular ML Experiments

Два самостоятельных проекта по табличному машинному обучению, в которых я последовательно прошёл полный цикл работы с данными: от EDA и проверки качества датасета до построения воспроизводимого пайплайна, сравнения моделей, подбора гиперпараметров и анализа полученных результатов.

Проекты специально отличаются по характеру данных:

- **Obesity Level Classification** — многоклассовая классификация на небольшом датасете со смешанными числовыми и категориальными признаками;
- **Santander Value Prediction** — регрессия на высокоразмерных, сильно разреженных и полностью анонимизированных данных.

Основной акцент сделан не только на итоговой метрике, но и на том, **почему модель показывает такой результат, какие решения действительно помогли и какие ограничения были обнаружены в процессе работы**.

---

## Проекты

# 1. Obesity Level Classification

[Проект](./obesity-classification/) ·
[Notebook](./obesity-classification/obesity_level_classification.ipynb)

Задача — классифицировать человека в один из семи уровней массы тела по антропометрическим данным, пищевым привычкам, физической активности и другим характеристикам образа жизни.

В проекте мне было важно не просто получить высокий score, а понять, **откуда именно он берётся и насколько этому результату вообще можно доверять**.

## Данные

Исходный датасет содержит:

- 2 111 строк;
- 16 входных признаков;
- 7 целевых классов;
- числовые и категориальные признаки;
- реальные и синтетически сгенерированные наблюдения.

При первичной проверке обнаружилось:

- пропущенных значений нет;
- найдено **24 полных дубликата**;
- после их удаления осталось **2 087 уникальных наблюдений**;
- классы достаточно хорошо сбалансированы.

Дубликаты были удалены **до train/test split**, чтобы идентичные строки не могли одновременно оказаться в обучающей и тестовой выборках.

Дополнительно был рассчитан признак:

```text
BMI = Weight / Height²
```

---

## Построение ML-пайплайна

Для числовых и категориальных данных использовалась раздельная предобработка через:

- `ColumnTransformer`;
- `SimpleImputer`;
- `StandardScaler`;
- `OneHotEncoder`;
- `Pipeline`.

Даже несмотря на отсутствие пропусков в текущем датасете, imputers оставлены внутри pipeline, чтобы схема предобработки оставалась устойчивой к новым данным.

Важный момент — вся предобработка выполняется **внутри sklearn Pipeline**, поэтому преобразования обучаются отдельно на каждом train-fold и не используют информацию из validation.

Для оценки использовался **5-fold cross-validation**, а test-выборка оставалась для финальной проверки уже выбранных конфигураций.

---

## Какие модели сравнивались

Были исследованы:

- Logistic Regression;
- Decision Tree;
- Random Forest.

Для каждой модели выполнялся подбор гиперпараметров по cross-validation.

Лучшие параметры Random Forest:

```text
n_estimators = 200
max_depth = 16
max_features = sqrt
min_samples_leaf = 1
```

Финальный Random Forest показал:

| Метрика | Значение |
|---|---:|
| 5-fold CV Macro-F1 | **0.9810** |
| Test Accuracy | **0.9785** |
| Test Macro-F1 | **0.9778** |

Разница между CV и test небольшая, поэтому результат оказался достаточно стабильным внутри данного датасета.

---

## Что удалось выяснить в процессе работы

До анализа я сформулировал **7 гипотез**, чтобы не ограничиваться простым перебором моделей и проверить конкретные предположения о данных.

Подтвердились **6 из 7**.

### 1. Антропометрические признаки действительно доминируют

В Random Forest наиболее важными признаками оказались:

```text
BMI       ≈ 0.310
Weight    ≈ 0.203
Gender    ≈ 0.062
FCVC      ≈ 0.057
Age       ≈ 0.054
Height    ≈ 0.051
```

Таким образом, два из трёх предполагаемых антропометрических признаков вошли в топ-3.

Но этот результат привёл к более важному наблюдению: **слишком высокая точность модели объясняется не только качеством алгоритма**.

Подробнее об этом — в разделе с ограничениями.

---

### 2. Logistic Regression неожиданно проиграла Decision Tree

Изначально я ожидал, что линейная модель будет хорошо разделять упорядоченные категории массы тела.

Получилось наоборот:

```text
Logistic Regression Macro-F1: 0.9487
Decision Tree Macro-F1:       0.9705
```

Это показало, что границы между классами лучше описываются нелинейными правилами, которые дерево способно восстанавливать напрямую.

То есть более сложная модель в данном случае оказалась оправданной структурой самих данных, а не просто дала случайное улучшение метрики.

---

### 3. Accuracy почти полностью согласуется с Macro-F1

Для лучшей модели:

```text
|Accuracy - Macro-F1| = 0.0007
```

Это подтверждает, что высокая accuracy не является следствием доминирования одного большого класса.

Именно поэтому для задачи можно одновременно смотреть на accuracy и Macro-F1, хотя основной метрикой я оставил Macro-F1.

---

### 4. Ограничение глубины действительно уменьшает переобучение дерева

Для Decision Tree отдельно сравнивался разрыв между train и test:

```text
Без ограничения глубины: gap = 0.0311
max_depth = 5:           gap = 0.0131
```

То есть ограничение сложности дерева более чем в два раза уменьшило разрыв между обучением и тестом.

Этот эксперимент хорошо показывает bias-variance trade-off на реальных результатах модели.

---

### 5. Большую часть качества Logistic Regression можно сохранить всего на 10 признаках

После `SelectKBest` модель использовала только 10 преобразованных признаков.

Полная Logistic Regression:

```text
Test Macro-F1 = 0.9487
```

После feature selection:

```text
Test Macro-F1 = 0.9431
```

Падение составило всего:

```text
-0.0056 Macro-F1
```

То есть значительную часть информации в преобразованном пространстве можно сохранить существенно меньшим числом признаков.

Среди выбранных оказались:

- Age;
- Weight;
- BMI;
- FCVC;
- Gender;
- family history with overweight;
- некоторые категории пищевого поведения.

---

### 6. Семейная история сильно связана с классами ожирения

Доля классов ожирения:

```text
без семейной истории избыточного веса: ≈ 2.2%
с семейной историей:                   ≈ 56.0%
```

Разница:

```text
0.538
```

Статистический тест:

```text
χ² p-value ≈ 1.14e-77
```

Связь в этом датасете очень сильная.

При этом я сознательно не интерпретирую её как причинно-следственную: статистическая ассоциация сама по себе не доказывает, что семейная история является причиной ожирения.

---

### 7. Физическая активность связана с уровнем массы тела, но эффект небольшой

Для `FAF` и порядкового уровня массы тела:

```text
Spearman ρ = -0.187
p-value ≈ 7.85e-18
```

Связь статистически значимая и направлена в ожидаемую сторону: более высокая физическая активность связана с меньшим уровнем массы тела.

Но величина корреляции небольшая, поэтому делать вывод о сильном индивидуальном влиянии этого признака нельзя.

---

## Главное обнаруженное ограничение

Изначально итоговый Macro-F1 около `0.98` выглядит как очень сильный результат.

Однако анализ feature importance показал, что основной вклад дают:

```text
BMI
Weight
Height
```

А `BMI` напрямую вычисляется из:

```text
Weight / Height²
```

При этом сами целевые категории массы тела тесно связаны с BMI.

Получается, что модель во многом учится **восстанавливать правило, близкое к тому, по которому сформированы сами классы**.

Это не классическая утечка данных из test в train, но это очень сильный **target proxy / shortcut**.

Поэтому результат:

```text
Macro-F1 = 0.9778
```

нельзя интерпретировать как способность модели независимо диагностировать состояние человека по его образу жизни.

Правильнее трактовать проект как исследование:

- поведения разных моделей;
- организации preprocessing без leakage;
- feature importance;
- feature selection;
- переобучения;
- проверки статистических гипотез;
- ограничений самого датасета.

# 2. Santander Value Prediction

[Проект](./santander-value-prediction/) ·
[Notebook](./santander-value-prediction/santander_value_prediction.ipynb)

Проект построен на данных **Santander Value Prediction Challenge**.

Это существенно другая задача: здесь признаки полностью анонимизированы, поэтому нельзя опираться на предметную область и интерпретировать столбцы по их смыслу.

Задача сводится к поиску устойчивого статистического сигнала в очень высокоразмерной и разреженной матрице.

---

## Исходные данные

Train:

```text
4 459 объектов
4 991 исходный признак
```

Test:

```text
49 342 объекта
```

Первый важный результат EDA — огромное количество практически пустых признаков.

Было обнаружено:

```text
4 991 исходных признаков
  256 константных
4 735 осталось после удаления константных
```

Средняя доля нулей в строке составляет примерно:

```text
96.7%
```

а медианная:

```text
97.8%
```

То есть типичный объект содержит ненулевые значения лишь в небольшой части из тысяч признаков.

Это определило дальнейшую стратегию feature engineering.

---

## Работа с target

Target имеет сильно скошенное распределение и большой диапазон значений.

Поэтому обучение и оценка выполняются в логарифмическом пространстве:

```python
y_log = np.log1p(y)
```

Это соответствует используемой метрике RMSLE и уменьшает влияние экстремально больших абсолютных значений.

---

## Feature engineering

Использовать все 4 991 признаков напрямую для каждой модели оказалось неоптимально как вычислительно, так и с точки зрения количества шума.

После анализа разреженности были выбраны **600 наиболее активных исходных признаков**.

Для них применялось преобразование:

```python
sign(x) * log1p(abs(x))
```

В отличие от обычного `log1p`, оно сохраняет знак значений.

Дополнительно я построил **9 агрегированных признаков по строке**:

```text
row_nonzero_count
row_zero_fraction
row_abs_sum
row_abs_mean
row_abs_std
row_abs_max
row_log_sum
row_log_mean
row_log_std
```

В результате вместо исходных 4 991 столбцов все модели получают единую матрицу:

```text
600 transformed raw features
  9 row-level features
------------------------
609 features
```

Размеры:

```text
train: (4459, 609)
test:  (49342, 609)
```

---

## Почему row-level features оказались важны

Так как названия исходных признаков полностью анонимизированы, отдельно было интересно проверить, несёт ли информация не конкретное значение одного столбца, а **общая структура значений внутри строки**.

Анализ feature importance показал:

```text
row_log_mean ≈ 0.405
row_abs_mean ≈ 0.067
row_log_std  ≈ 0.026
```

Причём `row_log_mean` оказался с большим отрывом самым важным отдельным признаком.

Это стало одним из ключевых выводов проекта:

> на сильно разреженных анонимизированных данных агрегированные характеристики распределения значений объекта могут содержать больше полезного сигнала, чем многие отдельные исходные колонки.

---

## Честное сравнение моделей

Чтобы сравнение алгоритмов было корректным, для всех моделей зафиксированы:

- одна и та же матрица из 609 признаков;
- одинаковые folds;
- одинаковая метрика;
- одинаковая процедура OOF evaluation.

Гиперпараметры предварительно подбирались на 3-fold CV, после чего лучшие конфигурации сравнивались на **5-fold OOF CV**.

Kaggle test при выборе победителя **не использовался**.

---

## Baseline

В качестве простейшей точки отсчёта использовался:

```text
DummyRegressor(strategy="median")
```

Средний RMSLE по пяти folds:

```text
≈ 1.7564
```

Это позволяет оценивать последующие модели не сами по себе, а относительно тривиального предсказания.

---

## Сравнение моделей

Были исследованы:

- Ridge Regression;
- ExtraTrees;
- Random Forest;
- HistGradientBoosting;
- LightGBM.

Финальные результаты:

| Модель | OOF CV RMSLE |
|---|---:|
| **Weighted Blend** | **1.336892** |
| ExtraTrees | 1.341706 |
| Random Forest | 1.342065 |
| LightGBM | 1.345767 |
| HistGradientBoosting | 1.350266 |
| Ridge | 1.431552 |
| Dummy median | ~1.7564 |

---

## Что получилось улучшить

По сравнению с простейшим median baseline:

```text
Baseline RMSLE      ≈ 1.7564
Final RMSLE          = 1.336892
Absolute improvement ≈ 0.4195
```

То есть RMSLE удалось уменьшить примерно на:

```text
23.9%
```

Отдельный интерес представляет то, что три лучших алгоритма показали очень близкое качество:

```text
ExtraTrees    1.341706
RandomForest  1.342065
LightGBM      1.345767
```

Вместо выбора одной модели я объединил их OOF-прогнозы в weighted blend.

Веса рассчитывались обратно пропорционально CV error:

```text
ExtraTrees    ≈ 0.3337
RandomForest  ≈ 0.3336
LightGBM      ≈ 0.3327
```

Результат:

```text
Best single model: 1.341706
Weighted blend:    1.336892
```

Ансамбль улучшил результат ещё примерно на `0.0048 RMSLE`.

Улучшение небольшое, но устойчивое по OOF, поэтому именно blend был выбран как финальная модель.

---

## Что показало сравнение алгоритмов

### Линейной модели оказалось недостаточно

Ridge:

```text
RMSLE = 1.431552
```

существенно уступил tree-based моделям.

Это показывает, что после построенного feature space зависимость остаётся достаточно нелинейной.

---

### Три разных tree-based подхода пришли почти к одному качеству

ExtraTrees, RandomForest и LightGBM находятся очень близко друг к другу.

Это полезный результат сам по себе: дальнейшее улучшение задачи, вероятно, стоит искать уже не просто в замене одного алгоритма другим, а в:

- более сильном feature engineering;
- работе с feature interactions;
- другом способе отбора исходных признаков;
- более продвинутом stacking/blending;
- анализе стабильности признаков между folds.

---

### Агрегаты по строке оказались важнее, чем ожидалось

Самым сильным отдельным признаком стал `row_log_mean`.

Это изменило взгляд на задачу: вместо попытки найти несколько «магических» анонимизированных колонок полезнее оказалось описывать **общую структуру разреженного объекта**.

---

## Финальный выбор модели

Победитель выбирался исключительно по OOF CV:

```text
Weighted Blend
OOF RMSLE = 1.336892
```

Только после завершения model selection компоненты ансамбля были заново обучены на всех:

```text
4 459 train-объектах
```

После чего сформирован итоговый prediction для Kaggle test.

Таким образом, test-set соревнования не использовался для ручного подбора модели.

# Что объединяет оба проекта

Хотя задачи сильно отличаются, при работе над ними я старался придерживаться одинаковых принципов:

### Корректная валидация

Model selection проводится по cross-validation, а test не используется для выбора гиперпараметров.

### Единый preprocessing

Преобразования выполняются воспроизводимо и одинаково для train и inference.

### Baseline перед усложнением

Сначала строится понятная точка отсчёта, после чего оценивается реальный эффект более сложных решений.

### Сравнение моделей в одинаковых условиях

Нельзя честно сравнивать два алгоритма, если один получил более сильный feature engineering или другие folds.

### Анализ неудачных гипотез

Отрицательный результат тоже является результатом.

Например, в Obesity ожидалось преимущество Logistic Regression над Decision Tree, однако эксперимент показал обратное.

### Анализ ограничений

Высокая метрика сама по себе не означает хорошую модель.

В Obesity высокий score во многом объясняется структурой разметки и BMI, а в Santander качество CV ограничено маленькой train-выборкой при очень большом числе исходных признаков.
